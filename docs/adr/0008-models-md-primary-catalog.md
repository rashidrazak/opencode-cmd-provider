# ADR-0008: models.md-primary Model catalog with enrichment-only sources

Status: accepted

The plugin used to decide which Command Code models exist from the provider listing API: when the API lagged the published npm package catalog (models.md) or the Command Code models page, the Snapshot dropped the model entirely — auto-registration never emitted it, enrichment for it was discarded, and coverage gates failed or silently hid it. Availability — the primary objective — was held hostage by the least-fresh source. The decision: **the npm package models.md table is the sole membership authority for the Snapshot** (every row ships its id, name, context, costs, efforts), and the listing API, the docs' RSC slug records, the CLI bundle, and the models page are **enrichment sources** — supportive data that fills gaps and confirms facts but never decides membership, never wins a ship-bar field, and never gates the refresh. This supersedes the membership halves of ADR-0001 (the API-shaped snapshot assumption), ADR-0005 (the "fails loudly when a snapshot model has no RSC record" coverage gate), ADR-0006 (the "total-coverage gate" and "RSC-only derivation" halves), and the ADR-0003 facts-amendment gate ("fails if an API snapshot model is absent from the CLI modality catalog"); those ADRs keep their original text with forward supersede-notes so the history stays readable.

## Source-authority table

Each shipped field value traces to exactly one row. Sources are consulted in order; the first source that resolves wins, and every non-primary resolution is annotated (row provenance in the snapshot module, log lines, and the six refresh-diff sections) so a maintainer can trace any value to its row.

Banded/peak pricing (DeepSeek peak/off-peak, long-context bands) flows only through the existing RSC peak/off-peak and over-context deals fields — no second band parser exists. Models page rate cells carrying footnote markers ship their base rate through the cost ladder with a "banded pricing, verify against RSC" note in the refresh diff.

## Parser shape discipline

A _parse_ failure of a successfully-fetched source is always loud (exit 1, naming the model): an unknown models.md Context token, an unparseable price cell, a consumed RSC slug record missing a required field (including the `reasoning` flag), an unknown models page Caps label (shape-pinned to {Text input, Vision, Reasoning}), an unmapped models page slug (the slug-to-id map is pinned), or a conflicting CLI-bundle entry. These are parser work, never silent defaults — a renamed upstream field needs code, by design. A _fetch_ failure of an enrichment source inside the snapshot ladders (network/4xx/5xx on RSC, CLI, models page, detail pages) degrades to the next ladder step with a note — never loud. Two carve-outs survive deliberately: the standalone live generators keep ADR-0005's fetch contract (RSC 4xx is a config error — route moved or a `COMMANDCODE_RSC_*_URL` override is wrong — so the classification/deals passes fail loudly and write nothing, while 5xx/network falls back to the committed fixtures), and the listing API is note-only even on shape skew (divergence skipped), because it writes no field at all.

## Only two loud failure classes survive

1. **An unshippable row** — a models.md row missing id/name/context/cost after its full ladder (the ship-bar). Names the row, aborts before anything is written: no partial refresh, no silent pending rows.
2. **A parser shape change in any source** — names the model and the unparseable value. Missing means "ladder engages"; unparseable means "parser work".

Everything else — missing enrichment, CLI outages, API skew in either direction, stale carried-forward context, banded-pricing caveats — is tolerated-with-fallback plus refresh-diff noise.

## Pipeline order and retirement

Membership reads first (registry dist-tag → models.md), then enrichment attaches lazily and live: the RSC slug pages and models page index are fetched only when a row actually needs a ladder step (detail pages only on cost-ladder use, live-fetch-only, never pinned), while the CLI bundle is always fetched for modalities. The classification and deals passes regenerate from the freshly captured fixtures in cron (`npm run refresh` = snapshot → fixture capture → fixtured classification → fixtured deals); the models page fixture is ride-along in drift judgment (never meaningful alone) and detail pages are never pinned. A package-table row removal prunes the Snapshot immediately: the refresh diff carries a loud "Removed models" section, the added/removed/changed tables flow through the PR body into the auto-release CHANGELOG entry, and declared-model merge semantics (user entries win and survive) keep existing configs working. The other five diff sections — pending enrichment per model, carried-forward context, cost-fallback provenance, API divergence (both directions), banded-pricing notes — render deterministically and empty-quiet, so routine refreshes stay one-click merges.

## Consequences

- Day-1 models (in models.md, not yet on the API, no RSC record) ship with efforts-driven reasoning and a pending tail — availability no longer waits on docs lag.
- A red cron now means "needs code" (shape) or "needs a ship-bar decision" (unshippable row), never "needs data".
- Gate tests assert the new trust order: costs fully asserted (membership implies cost coverage by construction); classification, deals, and modalities asserted as subsets of membership with pending reports.
- Erratic-value debugging starts and ends at the table above: find the field, walk its ordered sources, read the provenance annotation on the shipped row.
