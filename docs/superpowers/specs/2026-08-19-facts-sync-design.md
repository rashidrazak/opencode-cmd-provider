# Design: auto-sync capability facts at snapshot refresh

Date: 2026-08-19

Status: proposed

## Problem

The plugin's capability matrix — reasoning efforts (`MODEL_EFFORTS`), pricing
(`MODEL_COSTS`), and image modalities (`MODEL_INPUT_MODALITIES`) — was
hand-maintained. Command Code changes its catalog; the tables went stale with
no detection. Evidence: `gpt-5.6-terra`/`luna` discount rows expired
2026-08-14, and `deepseek-v4-pro`/`flash` rates drifted from the live page;
only a manual verification caught it.

## Goals

- Capability facts (reasoning efforts, pricing, context, and image modalities)
  update automatically when the snapshot refresh runs, exactly like
  `src/catalog/snapshot.ts`.
- Drift is detected and compared at refresh/release time; shipping a new
  release version is how drift lands.
- Runtime never touches the network.

## Facts source

The command-code npm package (the official Command Code CLI, `bin: cmd`)
ships a generated knowledge bundle:
`dist/bundled/command-code-knowledge/reference/models.md`.

Provenance: Command Code's internal model registry → docs
(commandcode.ai) → bundled knowledge in the CLI npm package. It is the same
data the CLI itself uses to resolve model ids, reasoning efforts, and
advertised per-1M-token rates ("promos are already baked in", per the file
footer).

Fetched at refresh time from:
`https://unpkg.com/command-code@<latest>/dist/bundled/command-code-knowledge/reference/models.md`

Input modalities are fetched from the same package's CLI bundle:
`https://unpkg.com/command-code@<latest>/dist/cli.mjs`.

Columns parsed: Id, Name, Context, Efforts, $/1M in/out · cache read (write).

- Efforts: `low, medium, high, xhigh, max` or `—` (no explicit efforts).
- Pricing: `$X.XX/$Y.YY · cache $Z.ZZ` plus optional `(write $W.WW)`; absent
  write → 0. Free models: `$0/$0 · cache $0`.
- Context: already sourced from the Provider API (snapshot); models.md context
  column is display-formatted (`1M`, `262K`) and is ignored by the facts
  parser — the API remains authoritative for context.

## Design

### 1. Generated facts file: `src/catalog/facts.ts`

New generated file (same header style as `snapshot.ts`: "GENERATED by
scripts/refresh-snapshot.mjs. Do not edit."):

- `MODEL_EFFORTS: Readonly<Record<string, readonly string[]>>` — from the
  Efforts column; models with `—` omitted (existing semantics: omitted models
  let Command Code choose their depth).
- `MODEL_COSTS: Readonly<Record<string, CommandCodeModelCost>>` — flat rates
  only: input, output, cacheRead, cacheWrite. No tiers (Command Code does not
  publish context-dependent tiers; the existing tier entries were ported from
  pi without a verifiable source).
- Header records facts source URL, fetched package version, and fetch date:
  `FACTS_SOURCE_URL`, `MODALITIES_SOURCE_URL`, `FACTS_PACKAGE_VERSION`,
  `FACTS_LAST_REFRESHED`.
- `MODEL_INPUT_MODALITIES: Readonly<Record<string, readonly ("text" | "image")[]>>`
  — image-capable entries from `inputModalities` in the CLI bundle. Text-only
  models are omitted and retain the provider's `['text']` fallback.
- The model list mirrors the Provider API snapshot (both derive from the same
  registry); any model missing from `models.md` has no cost/effort entry and
  is caught by the existing coverage tests.

### 2. Provider modules import the generated facts

- `src/provider/reasoning.ts`: delete the hand-written `MODEL_EFFORTS` table;
  import and re-export from `../catalog/facts.js` so existing importers
  (`tests/catalog-metadata.test.ts` imports `MODEL_EFFORTS` from reasoning.js)
  keep working. `REASONING_MODELS`, `isReasoningModel`,
  `reasoningVariantsForModel` stay as-is (hand-maintained classification).
- `src/provider/pricing.ts`: delete the hand-written `MODEL_COSTS` table;
  import and re-export from `../catalog/facts.js`. Keep `ZERO_MODEL_COST`,
  `CommandCodeModelCostRates`, `CommandCodeModelCost` interfaces. Delete
  `CommandCodeModelCostTier` and the `tiers?` field (dead after facts
  generation). Replace `PRICING_SOURCE_URL`/`PRICING_LAST_VERIFIED` with the
  facts header constants re-exported from facts.ts (checked: both are exported
  but unused elsewhere).
- `src/provider/cost.ts`: remove the tier loop (dead once no model has tiers);
  cost calculation becomes flat-rate. Update `tests/cost.test.ts` — delete the
  "tiers select the highest threshold exceeded" test; the flat-rate tests stay.

### 3. Refresh script: `scripts/refresh-snapshot.mjs`

After the existing Provider API fetch + snapshot write, the script:

1. Resolves the latest `command-code` version from the npm registry
   (`https://registry.npmjs.org/command-code`, `dist-tags.latest`).
2. Fetches `models.md` at that version (unpkg).
3. Parses the markdown tables into efforts + costs.
4. Fetches and parses `dist/cli.mjs` input-modality fields with an AST parser.
5. Verifies every Provider API snapshot model exists in the CLI modality
   catalog.
6. Writes `src/catalog/facts.ts` (default `--facts-out`, overridable for
   tests; env override for the registry/unpkg base URLs, mirroring
   `COMMANDCODE_API_BASE`).
7. Prints a summary: models written, efforts entries, cost entries, and the
   fetched package version — so the release ritual can eyeball the drift.

Failure behavior mirrors the existing script: network/parse errors fail with
an explicit message and non-zero exit; no partial files are written (parse
fully, then write both files).

### 4. Release gate (ADR 0003 extension)

The release pipeline already refreshes the snapshot in place and fails loudly
if it drifted. Extend it to also regenerate `facts.ts` and fail if the
committed file differs (instructions: run `npm run refresh:snapshot`, commit,
land on main, re-tag). Same guarantee as the snapshot: a stale facts file can
neither ship nor be forgotten.

ADR 0003 gets a short amendment paragraph documenting the facts gate.

### 5. Hand-maintained residue (documented, not automated)

No deterministic fetchable source exists for:

- `REASONING_MODELS` / `NON_REASONING_MODELS` (reasoning-capable-without-
  explicit-efforts classification) — judgement call, not published as data.

The existing coverage tests (`tests/catalog-metadata.test.ts`) continue to
guarantee every snapshot model resolves modalities/reasoning/cost — so a new
model entering via facts generation fails the suite until its generated facts
are refreshed, forcing the release to carry the metadata.

## Testing

- `tests/refresh-snapshot.test.ts` — extended: facts parsing (efforts,
  flat pricing, `(write ...)` handling, `—`/absent write, free models),
  generated-file rendering, modality coverage, failure on unparseable input,
  env overrides.
- `tests/parse-modalities.test.ts` — AST parsing, field reordering, duplicate
  entries, unsupported values, and malformed bundles.
- `tests/cost.test.ts` — tier test removed; flat-rate arithmetic unchanged.
- `tests/catalog-metadata.test.ts` — verifies snapshot coverage against the
  generated facts; the vision assertions now derive from the generated
  modalities (the hand-maintained fixture was removed with the table).
- `tests/plugin-models.test.ts` — unchanged.

## Out of scope

- Fetching facts at runtime (runtime stays offline).
- The three extra models on the docs pricing page (Claude Sonnet 4.5, Claude
  Opus 4.6, Ling 3.0 Flash) that the Provider API and models.md do not
  expose; they appear only when the CLI catalog ships them.
